# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Outfolio — public portfolio/case-study platform for OutSystems developers. Turns private OML project notes into structured, privacy-safe public case studies (problem/solution/screens/data model/integrations/role/impact), with an AI draft generator.

All app code lives in `frontend/` (repo root has no other apps). This project is scaffolded/managed by **Lovable** (Lovable Cloud + Lovable AI Gateway) — several files carry `// This file is automatically generated. Do not edit it directly.` headers (Supabase client/middleware files, `ai.functions.ts`-style server functions). Treat those as generated: prefer regenerating via Lovable over hand-editing when possible, but if you must edit, keep the pattern intact.

## Commands (run from `frontend/`)

- `bun install` — install deps (this repo uses Bun, see `bun.lock`/`bunfig.toml`)
- `bun run dev` — start dev server (vite dev)
- `bun run build` — production build
- `bun run build:dev` — development-mode build
- `bun run preview` — preview a production build
- `bun run lint` — eslint over the repo
- `bun run format` — prettier --write

No test runner is configured in this repo.

### Supply-chain guard

`bunfig.toml` sets `minimumReleaseAge = 86400` — new package installs must be >24h old. To add a package published more recently, it must be added to `minimumReleaseAgeExcludes` in `bunfig.toml`; **confirm with the user before adding an exclusion**.

## Architecture

### Stack

TanStack Start (file-based SSR React framework) + TanStack Router + TanStack Query, Tailwind CSS v4, shadcn/ui (new-york style, Radix primitives) on top of Supabase (Postgres + Auth + Storage), deployed via Nitro (Cloudflare target by default).

### Vite config is mostly hidden

`frontend/vite.config.ts` wraps `@lovable.dev/vite-tanstack-config`, which already bundles TanStack devtools, `tanstackStart`, `viteReact`, `tailwindcss`, `tsConfigPaths`, Nitro, `VITE_*` env injection, the `@` path alias, React/TanStack dedupe, error-logger plugins, and sandbox port/host detection. **Do not re-add any of these plugins manually** — duplicate plugins break the app. Only pass extra config through `defineConfig({ vite: {...}, tanstackStart: {...} })`.

### Routing

File-based routing via TanStack Router, rooted at `frontend/src/routes/`. See `frontend/src/routes/README.md` for the full convention table. Key points:
- `index.tsx` → `/`, `users/$id.tsx` → `/users/:id` (bare `$`, no curly braces), `files/$.tsx` → splat route (read via `_splat`, never `*`)
- `__root.tsx` is the only root layout/app shell (defines `<html>`, head tags, `<Outlet />`, global error/not-found components) — don't create `src/pages/` or Next/Remix-style layout files
- `routeTree.gen.ts` is auto-generated — never hand-edit it
- Current routes: `/` (index), `/developers`, `/try` (AI generator demo), `/u/$username`, `/u/$username/$slug`, `sitemap.xml`

### Server entry / error handling (SSR)

There's a deliberate two-layer error-handling setup that matters if you touch SSR:
- `frontend/src/start.ts` defines `startInstance` (via `createStart`) with `functionMiddleware: [attachSupabaseAuth]` and `requestMiddleware: [errorMiddleware, csrfMiddleware]`. Defining `src/start.ts` at all opts out of Start's automatic CSRF middleware, so `createCsrfMiddleware` is re-added explicitly — don't remove it.
- `frontend/src/server.ts` wraps the generated Start server entry. h3 (the underlying server) swallows in-handler throws into a generic `{"unhandled":true,"message":"HTTPError"}` 500 response with no stack — a plain `try/catch` around the handler won't see the real error. `frontend/src/lib/error-capture.ts` patches `console.error` to record the last real Error out-of-band (5s TTL) so `server.ts` can recover it (`consumeLastCapturedError`) when it detects this swallowed-error shape, and renders a proper error page (`frontend/src/lib/error-page.ts`) instead.
- Client-side render errors go through `__root.tsx`'s `errorComponent`, which reports via `frontend/src/lib/lovable-error-reporting.ts`.

### Supabase integration

`frontend/src/integrations/supabase/` — four files, three of them generated:
- `client.ts` — browser/client-side Supabase client (localStorage session persistence). Import as `import { supabase } from "@/integrations/supabase/client"`.
- `client.server.ts` — **service-role** admin client that bypasses RLS. Server-only; top-level import is only safe from other `*.server.ts` modules (route files and `*.functions.ts` ship to the client bundle) — load it dynamically inside server handlers instead: `const { supabaseAdmin } = await import("@/integrations/supabase/client.server")`.
- `auth-middleware.ts` — `requireSupabaseAuth`, a server-side function middleware that validates the caller's Bearer JWT (via `supabase.auth.getClaims`) and injects `{ supabase, userId, claims }` into server function context. Use this in server functions that need an authenticated, RLS-respecting Supabase client.
- `auth-attacher.ts` — `attachSupabaseAuth`, a client-side function middleware (registered globally in `start.ts`) that attaches the current session's Bearer token to every server function RPC. Without this registered, server functions never see the auth header.
- ESLint enforces that Next.js's `server-only` package is never imported — use the `*.server.ts` naming convention or `@tanstack/react-start/server-only` instead.

Migrations live in `frontend/supabase/migrations/`. Core schema: `developers` (public profiles), `projects` (belongs to a developer, has `visibility`/`anonymized`/`status`, unique on `developer_id, slug`), `project_sections` (ordered prose blocks per project), `artifacts` (uploaded evidence, public/private `visibility`). RLS is enabled on all tables — public reads are via explicit `FOR SELECT USING (...)` policies (e.g. projects only readable when `visibility = 'public'`); admin/service-role bypasses RLS entirely.

Domain types and Supabase query helpers (`fetchDevelopers`, `fetchDeveloperByUsername`, `fetchProject`, `fetchFeaturedProjects`) live in `frontend/src/lib/portfolio.ts`, alongside local asset overrides (`AVATAR_OVERRIDES`/`COVER_OVERRIDES`) used to substitute bundled images for seeded demo rows without hardcoding CDN paths in migrations.

### AI case-study generator

`frontend/src/lib/ai.functions.ts` defines a TanStack `createServerFn` (`generateCaseStudy`) that calls the Lovable AI Gateway (`https://ai.gateway.lovable.dev/v1/chat/completions`, `LOVABLE_API_KEY` env var) with a system prompt constrained to only use facts the developer supplied (no invented client names/metrics), flagging sensitive-looking details as redaction warnings. Input is validated with a Zod schema. Handles 429 (rate limit) and 402 (credits exhausted) as user-facing errors.

### Path aliases

`@/*` maps to `frontend/src/*` (see `tsconfig.json` and shadcn's `components.json`). shadcn is configured for `new-york` style, slate base color, CSS variables, no RSC.

### Styling

Tailwind v4 via `@theme inline` tokens in `frontend/src/styles.css`, layered under shadcn's CSS-variable color system. Custom semantic classes on top of shadcn tokens (`bg-canvas`, `text-ink`, `text-ink-muted`, `border-hairline`, `.eyebrow`, etc.) — check `styles.css` before introducing new ad-hoc utility combinations for these editorial/docs-style surfaces. Fonts (Inter, JetBrains Mono) are loaded via Google Fonts `<link>` tags in `__root.tsx`, not self-hosted.

### Linting

`eslint.config.js`: `@typescript-eslint/no-unused-vars` is off, `react-refresh/only-export-components` is a warning (constant exports allowed), Prettier runs as an ESLint rule (`eslint-plugin-prettier/recommended`) rather than a separate check.
